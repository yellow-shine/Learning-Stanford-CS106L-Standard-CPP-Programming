# 移动语义与拷贝

现在进入 C++ 最重要，也最容易混乱的一块。

假设：

```cpp
std::vector<int> a(1'000'000);
```

里面有 100 万个 int。

如果：

```cpp
std::vector<int> b = a;
```

这是 copy：

```text
a
 │
 ▼
heap
[100万个 int]

复制
 ↓

b
 │
 ▼
另一个 heap
[100万个 int]
```

非常贵。

---

但有时候我们知道：

> `a` 后面不用了。

那么为什么还复制？

可以直接把内部资源转给 `b`：

```cpp
std::vector<int> b = std::move(a);
```

大概发生：

```text
before:

a
 |
 v
[ huge buffer ]


move


a             b
              |
              v
        [ huge buffer ]
```

buffer 没复制。

只是把：

```text
pointer
size
capacity
```

转移过去。

---

## 移动后的源对象

比如：

```cpp
std::string a = "hello";

std::string b = std::move(a);
```

之后：

```cpp
a
```

处于：

> valid but unspecified state

也就是：

```text
对象仍然合法
但内容不能假设
```

你可以：

```cpp
a = "new value";
```

可以析构：

```cpp
// OK
```

实际移动后，不要依赖 `a` 仍然保留原来的内容。单独写 `std::move(a);` 不会移动或改变 `a`。

这里的“有效但状态未指定”适用于标准库类型的一般约定（另有规定除外）；自定义类型应明确自己的移动后状态。无前置条件的操作仍可使用，有前置条件的操作需先检查。

---

## 与 Go 的对比

Go 没有这种语言层面的 move semantics。

比如 C++：

```cpp
std::vector<int> a(...);

auto b = std::move(a);
```

表达的是：

```text
把 a 内部资源的 ownership
转移给 b
```

C++ 特别需要这一套，是因为它：

```text
没有 GC
+
对象可能自己管理资源
+
非常关注 zero-cost abstraction
```

所以它需要语言层面区分：

```text
这个对象还要用

vs

这个对象可以被消耗
```

于是才有：

```text
T&
T&&
std::move
move constructor
```

这一整套机制。
