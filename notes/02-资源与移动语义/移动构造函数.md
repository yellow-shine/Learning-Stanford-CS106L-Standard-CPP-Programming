# 移动构造函数

来看：

```cpp
class Buffer {
public:
    Buffer(Buffer &&other) {
        ...
    }
};
```

意思是：

> 我只希望在调用方明确提供一个“可以被搬走”的 Buffer 时进入这个构造函数。

例如：

```cpp
Buffer a(1024);

Buffer b(std::move(a));
```

那么：

```cpp
std::move(a)
```

可以绑定：

```cpp
Buffer &&other
```

因此：

```cpp
other
```

引用的就是原来的：

```cpp
a
```

可以画成：

```text
a
│
│ std::move(a)
│
▼
Buffer&& other
```

这不是创建另外一个 Buffer。

`other` 只是 `a` 的引用。

---

## 转移资源而非复制资源

假设：

```cpp
class Buffer {
public:
    Buffer(size_t size)
        : data_(new char[size]),
          size_(size) {}

private:
    char *data_;
    size_t size_;
};
```

对象：

```cpp
Buffer a(1000000);
```

大概：

```text
a

data_ ──────────────► [ 1 MB memory ]
size_ = 1000000
```

如果 copy：

```cpp
Buffer b(a);
```

需要：

```text
a                          b

data_ ──► [1MB]            data_ ──► [another 1MB]
                 COPY →
```

要复制 1 MB。

---

但如果：

```cpp
Buffer b(std::move(a));
```

进入：

```cpp
Buffer(Buffer &&other)
```

可以直接：

```cpp
data_ = other.data_;
size_ = other.size_;
```

于是：

```text
原来：

a
data_ ─────► [1 MB]


move 后：

a                       b
data_ = nullptr          data_ ─────► [1 MB]
```

并没有复制 1 MB。

只是复制了一个指针：

```cpp
char *
```

---

## 避免重复释放

这是另一个核心点。

如果：

```cpp
data_ = other.data_;
```

之后不清空：

```cpp
other.data_
```

那么：

```text
a.data_ ─────┐
             ├────► [memory]
b.data_ ─────┘
```

两个对象都认为：

> 这块内存是我的。

析构时：

```cpp
delete[] a.data_;
delete[] b.data_;
```

就会：

```text
double free
```

所以 move constructor：

```cpp
Buffer(Buffer &&other)
    : data_(other.data_),
      size_(other.size_) {
    other.data_ = nullptr;
    other.size_ = 0;
}
```

本质上是：

```text
把资源所有权从 other 转移到 this
```

---

## 示例的适用范围

上面的 `Buffer` 是讲解资源转移的片段，不是完整的资源管理类：实际类还必须有析构函数，并正确实现或禁用拷贝构造、拷贝赋值及移动赋值，避免泄漏和浅拷贝导致的重复释放。

不抛异常的移动操作应标记 `noexcept`，这也可能影响标准容器扩容时选择移动还是拷贝。实际开发优先让 `std::vector`、`std::unique_ptr` 等管理资源，避免手写裸指针所有权。
