# 5.6 建议（Advice）

## 学习目标

形成类设计的检查清单：先确定语义和不变量，再选择具体类型或多态层次，并明确资源所有权。

## 核心知识点

- **先定不变量**：先写清对象何时有效，再让构造和公开操作共同维护该条件。
- **最小接口**：只公开调用者真正需要的操作；较少的入口更容易测试、演化和保持一致。
- **值类型优先**：固定、简单且复制有意义的对象优先采用具体类型，避免不必要的间接访问。
- **多态按需**：仅在需要运行时替换实现时使用虚函数；编译期变化可考虑模板，单一实现则无需抽象层。
- **明确所有权**：值成员或智能指针直接表达生命周期；裸指针和引用通常只表示非拥有关系。
- **编译器检查**：使用 `const`、`override`、`final`、`explicit` 等语言机制把设计意图变成可诊断约束。

## 最小示例

```cpp
#include <memory>
struct Printer { virtual void print(int) = 0; virtual ~Printer() = default; };
class Job {
    std::unique_ptr<Printer> out_;
public:
    explicit Job(std::unique_ptr<Printer> p) : out_{std::move(p)} {}
    void run(int n) { out_->print(n); }
};
```

## 常见陷阱

- 不要预先为“以后可能有多个实现”建立继承体系；需求出现后再抽象。
- 不要让构造函数接受含糊的布尔参数或悄悄建立无效对象。
- 不要同时用裸指针和智能指针声称拥有同一资源。
