# 2.6 建议（Advice）

## 学习目标

根据数据约束选择最简单的用户类型，并让非法状态难以构造、资源所有权一目了然。

## 核心知识点

- **按概念建模（model concepts）**：相关数据和操作应形成一个有名称的类型，避免用相同基础类型混淆不同语义。
- **最小接口（minimal interface）**：只公开完成职责所需的操作，减少调用者与表示细节的耦合。
- **不变量优先（invariant first）**：需要验证的状态由构造函数建立，修改操作必须保持规则成立。
- **聚合优先（prefer aggregates）**：若没有不变量且公开字段就是合理接口，简单 `struct` 胜过样板式封装。
- **作用域枚举优先（prefer scoped enums）**：有限选项默认使用 `enum class`，避免名称泄漏和隐式整数转换。
- **标准变体优先（prefer std::variant）**：需要多种候选类型时，优先使用库设施而非手工联合体。

## 最小示例

```cpp
#include <stdexcept>

struct Point { double x, y; };
class Radius {
    double value_;
public:
    explicit Radius(double v) : value_{v} {
        if (v < 0) throw std::invalid_argument{"radius"};
    }
    double value() const { return value_; }
};
int main() { Point p{1, 2}; Radius r{3}; return p.x < r.value() ? 0 : 1; }
```

## 常见陷阱

- 为每个字段机械编写 getter/setter，却没有真正封装任何规则。
- 用继承表达单纯的数据组合，增加生命周期和耦合复杂度。
- 让一个类型同时承担值、资源句柄和全局协调等多个职责。
