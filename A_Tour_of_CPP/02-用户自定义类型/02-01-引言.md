# 2.1 引言（Introduction）

## 学习目标

理解用户自定义类型如何把数据与合法操作组织成领域概念，并认识表示与接口分离的价值。

## 核心知识点

- **用户自定义类型（user-defined type）**：类、结构体、枚举和联合体让程序可用领域词汇表达数据及规则。
- **表示（representation）**：类型内部成员保存状态；良好设计避免调用者依赖可变实现细节。
- **接口（interface）**：公开操作描述类型能做什么，应尽量小、稳定并体现使用约束。
- **不变量（invariant）**：对象在可观察操作前后都应满足的条件，通常由构造函数建立、成员函数维护。
- **值类型（value type）**：可自然复制、比较和独立存在的类型，使用体验接近内建类型。
- **封装（encapsulation）**：限制对表示的直接访问，使局部修改不破坏所有调用代码。

## 最小示例

```cpp
#include <stdexcept>

class Percentage {
    int value_;
public:
    explicit Percentage(int v) : value_{v} {
        if (v < 0 || v > 100) throw std::out_of_range{"percentage"};
    }
    int value() const { return value_; }
};

int main() { Percentage p{80}; return p.value() == 80 ? 0 : 1; }
```

## 常见陷阱

- 仅把多个字段打包，却不明确合法状态和支持的操作。
- 公开所有数据后再依赖注释要求调用者维护不变量。
- 为简单值类型引入无必要的继承层次和动态分配。
