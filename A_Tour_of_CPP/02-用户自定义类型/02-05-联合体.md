# 2.5 联合体（Unions）

## 学习目标

理解联合体共享存储的模型、活动成员限制，以及为何通常应优先使用受类型约束的变体。

## 核心知识点

- **联合体（union）**：所有非静态数据成员共享同一存储区域，大小足以容纳最大的成员并满足对齐。
- **活动成员（active member）**：任一时刻通常只有一个成员的生命周期处于活动状态，读取其他成员往往是未定义行为。
- **判别联合体（tagged union）**：需额外标签记录当前成员；手工实现必须同步维护标签、构造和析构。
- **变体（std::variant）**：标准库提供类型安全的判别联合体，自动管理活动值的生命周期。
- **访问器（std::get）**：按错误类型访问会抛出 `std::bad_variant_access`；`std::get_if` 可无异常地探测。
- **低层用途**：裸联合体主要用于严格控制表示或与外部 ABI 互操作，普通业务数据不应优先采用。

## 最小示例

```cpp
#include <iostream>
#include <string>
#include <variant>

int main() {
    std::variant<int, std::string> value = std::string{"ok"};
    if (auto* text = std::get_if<std::string>(&value))
        std::cout << *text << '\n';
}
```

## 常见陷阱

- 写入一个联合体成员后读取另一个成员来做可移植类型双关。
- 裸联合体包含非平凡类型时忽略手工构造、销毁和异常安全。
- 标签与实际活动成员不同步，导致错误析构或无效读取。
