# 12.9 建议（Advice）

## 学习目标

把容器选择建立在语义、复杂度与测量之上，并通过安全迭代和容量规划避免常见错误。

## 核心知识点

- **默认 vector**：没有特殊需求时优先使用 `vector`，连续存储、简洁接口和缓存局部性常带来最佳综合表现。
- **按操作选型**：需要排序遍历选有序关联容器，需要平均快速键查找可选哈希容器，两端队列考虑 `deque`。
- **预留容量**：已知近似大小时对 `vector` 或哈希容器调用 `reserve`，减少重分配或重哈希。
- **遵守失效规则**：修改容器前确认哪些迭代器、引用和指针仍有效；算法循环优先使用操作返回的新迭代器。
- **避免多余查找**：使用 `try_emplace`、`insert_or_assign` 和插入返回值，把查询与修改合并为一次操作。
- **先测量再替换**：节点容器或定制分配器不是天然优化；以真实负载和内存行为验证。

## 最小示例

```cpp
#include <vector>
int main() {
    std::vector<int> v{1,2,3,4};
    for (auto it = v.begin(); it != v.end(); ) {
        if (*it % 2 == 0) it = v.erase(it);
        else ++it;
    }
    return v == std::vector<int>{1,3} ? 0 : 1;
}
```

## 常见陷阱

- 范围 `for` 中删除当前容器元素通常会破坏迭代过程。
- 不要用 `operator[]` 对映射做纯查询，以免产生新元素。
- 不要把复杂度上界等同于实际速度，局部性与分配次数同样关键。
