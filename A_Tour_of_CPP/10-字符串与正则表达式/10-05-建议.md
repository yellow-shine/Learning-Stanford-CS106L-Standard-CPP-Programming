# 10.5 建议（Advice）

## 学习目标

建立现代 C++ 文本处理的选型与接口习惯，在清晰度、所有权和运行成本之间取得平衡。

## 核心知识点

- **明确所有权**：需要保存结果就返回 `std::string`；只在调用期间读取可接收 `std::string_view`。
- **按复杂度选工具**：字符判断、`find` 和分割足够时不用正则；模式确实复杂时再使用 `std::regex`。
- **避免重复编译**：频繁使用固定模式时复用已构造的正则对象，但共享使用前需考虑同步与实现特性。
- **长度优先**：与底层接口交互时同时传指针和长度，避免把所有文本都假定为无内嵌空字符的 C 字符串。
- **编码显式化**：在系统边界约定编码和错误策略，不把字节数误作自然语言字符数。

## 最小示例

```cpp
#include <string_view>
bool is_cpp(std::string_view name) {
    constexpr std::string_view suffix = ".cpp";
    return name.size() >= suffix.size() &&
           name.substr(name.size() - suffix.size()) == suffix;
}
int main() { return is_cpp("main.cpp") ? 0 : 1; }
```

## 常见陷阱

- 为避免一次小复制而返回悬空视图，代价远高于复制。
- 不要对用户输入直接套用未经成本评估的复杂正则。
- 大小写转换与 Unicode 规范化不是简单逐字节调用 `tolower` 就能完成。
