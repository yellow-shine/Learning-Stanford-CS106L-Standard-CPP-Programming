# 18.3 共享数据（Sharing Data）

## 学习目标

识别数据竞争，并用锁、原子或不可变设计建立线程间同步。

## 核心知识点

- 两个线程并发访问同一内存位置且至少一个写入，若无规定同步，便构成数据竞争并导致未定义行为。
- `std::mutex` 配合 `lock_guard` 或 `scoped_lock` 以 RAII 管理临界区，异常和早退也能释放锁。
- 多个锁应使用统一顺序或 `scoped_lock` 一次取得，避免循环等待造成死锁。
- 原子类型适合简单独立状态与计数，但内存次序和跨变量不变量通常仍需更高层同步。

## 最小示例

```cpp
#include <mutex>
#include <thread>
int main() {
    int total{}; std::mutex m;
    auto add = [&] { std::lock_guard lock{m}; ++total; };
    std::jthread a{add}, b{add};
    a.join(); b.join();
    return total == 2 ? 0 : 1;
}
```

## 常见陷阱

- 把 `volatile` 当同步工具、在持锁时调用未知外部代码，或只保护写入不保护读取，都会留下竞态或死锁风险。
- 受保护数据、互斥量和持锁对象的生命周期必须协调；销毁仍可能被其他线程使用的锁同样是未定义行为。
