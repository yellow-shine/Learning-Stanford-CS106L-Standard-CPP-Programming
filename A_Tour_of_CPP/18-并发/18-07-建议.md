# 18.7 建议（Advice）

## 学习目标

以所有权、同步边界和可停止性为中心设计并发代码，并用工具验证竞态。

## 核心知识点

- 先划分独立任务与所有权，优先传值、不可变数据和结果通道，再为确有必要的共享状态加锁。
- 优先 `jthread`、RAII 锁与带谓词条件等待，让异常、早退和正常结束遵循同一清理路径。
- 临界区保持短小，不持锁执行阻塞 I/O 或未知回调；多锁操作采用一致且可审查的获取方式。
- 并发测试不能证明没有竞态，应结合线程分析器、压力测试和清晰的 happens-before 推理。

## 最小示例

```cpp
#include <stop_token>
#include <thread>
int main() {
    std::jthread worker{[](std::stop_token stop) {
        while (!stop.stop_requested()) std::this_thread::yield();
    }};
    worker.request_stop();
}

```

## 常见陷阱

- 不要用休眠猜测线程已经完成，也不要为了性能过早选择无锁结构；先建立正确终止协议并测量瓶颈。
- 并发错误常依赖时序而难以复现；对象寿命、同步关系和关闭路径都必须明确验证。
