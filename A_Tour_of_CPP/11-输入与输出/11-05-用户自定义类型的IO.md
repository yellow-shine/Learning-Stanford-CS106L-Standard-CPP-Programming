# 11.5 用户自定义类型的 I/O（I/O of User-Defined Types）

## 学习目标

为自定义类型实现符合流惯例的插入与提取运算符，并确保解析失败不会留下半更新对象。

## 核心知识点

- **非成员运算符**：通常把 `operator<<`、`operator>>` 定义为非成员，使左操作数保持流类型并支持链式调用。
- **流引用返回**：两个运算符都返回原流引用，调用者才能继续插入、提取或检查状态。
- **临时解析**：提取时先读入临时变量，全部验证成功后再赋给目标对象，提供更清晰的失败语义。
- **失败标记**：格式不合法时设置 `failbit`，而不是静默接受损坏数据。
- **对称格式**：若文本用于往返存储，输出与输入格式应明确且互相兼容。

## 最小示例

```cpp
#include <iostream>
struct Point { int x{}, y{}; };
std::ostream& operator<<(std::ostream& os, Point p) { return os << p.x << ',' << p.y; }
std::istream& operator>>(std::istream& is, Point& p) {
    int x, y; char comma;
    if (is >> x >> comma >> y && comma == ',') p = {x, y};
    else is.setstate(std::ios::failbit);
    return is;
}
int main() { Point p; if (std::cin >> p) std::cout << p << '\n'; }
```

## 常见陷阱

- 不要在只读了一半时修改目标对象。
- 不要让运算符吞掉错误或擅自向诊断流打印消息。
- 分隔符也必须验证，仅读入一个 `char` 不代表格式正确。
