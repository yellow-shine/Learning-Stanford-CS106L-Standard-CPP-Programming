# 11.10 建议（Advice）

## 学习目标

建立可恢复、可测试且可移植的 I/O 设计习惯，把格式转换与设备访问适当分离。

## 核心知识点

- **检查每次边界操作**：打开、读取、解析、写入和关闭都可能失败；不要只验证文件是否存在。
- **流参数化**：业务格式化函数接受 `istream&` 或 `ostream&`，便于复用文件、控制台和字符串流进行测试。
- **状态后置处理**：输入失败时区分正常结束与坏数据；可恢复时清状态并消费问题输入。
- **最少刷新**：普通换行使用 `'\n'`，只有交互提示、日志时序或持久化要求明确时才刷新。
- **格式稳定性**：面向机器的数据应明确编码、区域设置、精度和版本，不依赖用户环境默认值。
- **文件系统错误**：可能失败的批量操作可用 `error_code` 持续处理；必须中止时异常接口更简洁。

## 最小示例

```cpp
#include <sstream>
#include <string>
bool read_count(std::istream& in, int& n) {
    std::string line;
    if (!std::getline(in, line)) return false;
    std::istringstream row{line};
    return static_cast<bool>(row >> n);
}
int main() { std::istringstream in{"42\n"}; int n; return read_count(in,n)&&n==42?0:1; }
```

## 常见陷阱

- 不要用异常替代所有可预期的用户输入校验。
- 不要把诊断信息写进承载机器协议的同一输出流。
- 临时文件写入若需防止损坏，应采用写临时文件后原子替换等策略。
