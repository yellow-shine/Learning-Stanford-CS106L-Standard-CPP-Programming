# 1.8 测试（Tests）

## 学习目标

用小而明确的检查验证正常、边界和失败路径，并理解测试与静态检查的互补关系。

## 核心知识点

- **测试用例（test case）**：给定输入并检查可观察结果，名称应说明被验证的行为。
- **边界值（boundary value）**：空输入、单元素、极值和临界点最容易暴露越界及条件错误。
- **断言（assertion）**：`assert` 适合检查开发期假设；定义 `NDEBUG` 后它通常不执行，不能承担输入验证。
- **编译期断言（static assertion）**：`static_assert` 在编译阶段验证常量条件或类型性质。
- **回归测试（regression test）**：修复缺陷时加入能复现原问题的最小测试，防止以后再次出现。
- **可测试设计（testable design）**：将纯计算与输入输出分离，能减少环境依赖并简化验证。

## 最小示例

```cpp
#include <cassert>

constexpr int clamp_zero(int x) { return x < 0 ? 0 : x; }

int main() {
    static_assert(clamp_zero(-1) == 0);
    assert(clamp_zero(5) == 5);
    assert(clamp_zero(0) == 0);
}
```

## 常见陷阱

- 只测试典型成功路径，遗漏空值、上下界和错误输入。
- 在 `assert` 表达式中放置有副作用的必要操作，发布构建可能将其删除。
- 用测试替代类型系统、编译器警告或运行期错误处理。
