# 4.5 断言（Assertions）

## 学习目标

用运行期与编译期断言记录不可违反的内部假设，同时不把它们误作外部输入处理机制。

## 核心知识点

- **运行期断言（assert）**：`<cassert>` 中的宏检查布尔表达式，失败时输出诊断并调用 `std::abort`。
- **发布配置（NDEBUG）**：定义该宏后 `assert` 通常展开为空，因此表达式不能包含程序所需副作用。
- **编译期断言（static_assert）**：验证可在编译期求值的条件，不满足时使编译失败并可附带消息。
- **内部假设（internal assumption）**：断言适合程序员确信必真的条件，失败通常意味着代码缺陷。
- **输入验证（input validation）**：文件、网络和用户数据不可信，必须始终检查并以可恢复方式报告错误。
- **前置条件（precondition）**：若违反可能来自正常调用错误，应由接口策略决定抛异常、返回错误或断言。

## 最小示例

```cpp
#include <cassert>
#include <cstddef>
#include <vector>

int first(const std::vector<int>& v) {
    assert(!v.empty());
    return v.front();
}
int main() {
    static_assert(sizeof(char) == 1);
    return first({4}) == 4 ? 0 : 1;
}
```

## 常见陷阱

- 用 `assert(read_data())` 执行必要操作，发布构建中调用会消失。
- 用断言检查用户输入，导致可预期错误直接中止程序。
- 断言一个实际上无法保证的条件，而不提供运行期恢复路径。
