# 4.3 不变量（Invariants）

## 学习目标

把对象始终必须满足的条件集中到类型边界，并保证失败操作不会留下半有效状态。

## 核心知识点

- **不变量（invariant）**：对象在构造完成后、公开操作调用前后必须成立的逻辑条件。
- **构造验证（construction validation）**：构造函数应验证输入；无法建立合法对象时应报告失败，而非产生待修复对象。
- **封装表示（encapsulated representation）**：私有成员阻止外部随意组合状态，是集中维护不变量的前提。
- **事务式修改（transactional update）**：先验证或先构造新状态，成功后再提交，避免中途失败破坏原对象。
- **类不变量与函数前提**：不变量由类型自身维护；调用前提则是调用者对一次操作必须满足的要求。
- **异常安全保证（exception-safety guarantee）**：基本保证维持有效状态，强保证还确保失败时无可观察变化。

## 最小示例

```cpp
#include <stdexcept>

class Fraction {
    int num_, den_;
public:
    Fraction(int n, int d) : num_{n}, den_{d} {
        if (d == 0) throw std::invalid_argument{"zero denominator"};
    }
    double value() const { return static_cast<double>(num_) / den_; }
};
int main() { return Fraction{1, 2}.value() == 0.5 ? 0 : 1; }
```

## 常见陷阱

- 允许默认构造出无效对象，再要求调用者记得初始化。
- 返回非常量内部引用，让外部绕过验证直接破坏状态。
- 修改多个成员后才验证，异常时遗留部分更新的对象。
