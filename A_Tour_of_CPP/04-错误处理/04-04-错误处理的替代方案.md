# 4.4 错误处理的替代方案（Error-Handling Alternatives）

## 学习目标

比较异常、可选值、错误码和终止策略，根据失败的可预期性与恢复位置选择接口。

## 核心知识点

- **可选值（std::optional）**：表示“有一个 `T` 或无值”，适合原因单一且缺失属于正常结果的查询。
- **错误码（error code）**：显式返回状态，适合系统接口或禁用异常环境，但调用者可能忘记检查。
- **复合结果（result object）**：自定义结构可同时承载值或详细错误；C++20 标准库尚无 `std::expected`。
- **哨兵值（sentinel value）**：用特殊普通值表示失败容易与合法数据混淆，除非接口已有明确约定。
- **终止（termination）**：对无法继续且无法安全恢复的内部故障，可记录信息后终止；不适合普通用户输入错误。
- **异常（exception）**：适合检测层与恢复层相距较远、失败无法作为普通返回值自然表达的情况。

## 最小示例

```cpp
#include <optional>
#include <string_view>

std::optional<int> digit(std::string_view s) {
    if (s.size() != 1 || s[0] < '0' || s[0] > '9') return std::nullopt;
    return s[0] - '0';
}
int main() {
    if (auto n = digit("7")) return *n == 7 ? 0 : 1;
    return 1;
}
```

## 常见陷阱

- 返回错误码却在调用链中忽略它，最终在远处以错误状态失败。
- 用 `optional` 表示多种失败原因，导致诊断信息丢失。
- 虚构 C++20 的 `std::expected`；它在 C++23 才进入标准。
