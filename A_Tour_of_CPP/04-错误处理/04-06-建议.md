# 4.6 建议（Advice）

## 学习目标

建立一致的错误处理纪律：先分类，再在合适边界报告，并确保所有失败路径保持资源与状态安全。

## 核心知识点

- **先分类后处理（classify first）**：区分可恢复环境错误、无结果、调用者违约和内部缺陷，避免一刀切策略。
- **就近检测（detect locally）**：在拥有足够信息验证条件的位置立即检测，但把恢复决策交给了解业务语境的层。
- **RAII 优先（prefer RAII）**：文件、锁和内存交给对象管理，让正常返回与异常退出共享同一清理机制。
- **保留诊断（preserve diagnostics）**：错误信息应包含失败操作及关键上下文，转换异常时保留原始原因。
- **不变量保护（protect invariants）**：操作失败后对象仍应可析构、可赋值，最好保持原值。
- **统一约定（consistent convention）**：同一接口族对类似失败采用相同机制，降低漏检和误用概率。

## 最小示例

```cpp
#include <fstream>
#include <stdexcept>
#include <string>

std::string first_word(const char* path) {
    std::ifstream in{path};
    if (!in) throw std::runtime_error{"cannot open file"};
    std::string word;
    if (!(in >> word)) throw std::runtime_error{"file has no word"};
    return word; // in 自动关闭
}
int main() {
    try { (void)first_word("missing.txt"); }
    catch (const std::exception&) { return 0; }
}
```

## 常见陷阱

- 捕获所有异常后静默忽略，使程序带着未知状态继续运行。
- 同一层混用异常、负数错误码和空字符串表达相同失败。
- 给不会真正履行不抛承诺的函数添加 `noexcept`。
