# 4.1 引言（Introduction）

## 学习目标

区分可恢复错误、契约违例与程序缺陷，并为不同失败选择合适的报告和恢复方式。

## 核心知识点

- **错误分类（error classification）**：文件不存在可能可恢复，越界索引通常是程序缺陷，两者不应采用相同策略。
- **错误报告（error reporting）**：异常、返回值、错误码和终止各有适用场景，应在接口中明确失败语义。
- **错误处理（error handling）**：检测点未必有足够上下文恢复，可将信息传递给更高层决策者。
- **异常安全（exception safety）**：失败后至少不泄漏资源、不破坏对象不变量；更强保证可让操作保持原状态。
- **资源自动管理（RAII）**：资源获取即初始化把清理绑定到对象析构，是异常路径可靠清理的基础。
- **契约（contract）**：调用前提、操作结果和不变量应被文档、类型及检查共同表达。

## 最小示例

```cpp
#include <iostream>
#include <stdexcept>

int divide(int a, int b) {
    if (b == 0) throw std::invalid_argument{"zero divisor"};
    return a / b;
}
int main() {
    try { std::cout << divide(8, 0); }
    catch (const std::exception& e) { std::cerr << e.what() << '\n'; }
}
```

## 常见陷阱

- 检测错误后静默返回看似合理的默认值，掩盖真实故障。
- 在底层组件擅自打印并退出，使上层无法选择恢复策略。
- 只设计成功路径，资源清理依赖每条分支手工执行。
