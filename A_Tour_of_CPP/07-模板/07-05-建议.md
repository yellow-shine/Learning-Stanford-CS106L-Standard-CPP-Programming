# 7.5 建议（Advice）

## 学习目标

以清晰约束和小型接口编写模板，在复用能力、诊断质量、编译成本与代码体积之间取得平衡。

## 核心知识点

- **先写要求**：模板参数应按所需操作约束，而不是按某个具体继承体系限制。
- **优先推导**：让函数实参推导类型，只有推导无法表达或需明确选择时才显式给模板实参。
- **标准算法优先**：标准容器、算法、范围和类型特征已覆盖常见模式，复用它们可减少自制模板机制。
- **小型模板**：把不依赖类型的代码移出模板，既减少重复实例化，也缩短错误回溯。
- **语义约束**：概念不仅检查表达式能否编译，还应命名并记录调用者必须遵守的语义。
- **避免技巧堆叠**：优先普通函数、重载和 `if constexpr`，仅在它们不足时使用复杂特化。

## 最小示例

```cpp
#include <concepts>
#include <ranges>
template<std::ranges::input_range R>
requires std::integral<std::ranges::range_value_t<R>>
long long sum(const R& r) {
    long long total = 0;
    for (auto x : r) total += x;
    return total;
}
```

## 常见陷阱

- 仅凭示例类型编译成功不能证明模板通用，应测试边界类型与约束失败情形。
- 无约束的万能引用重载可能吞掉本应选择的普通重载。
- 不要用模板解决只存在一个类型的需求；普通函数更便于编译和调试。
