# 13.6 并行算法（Parallel Algorithms）

## 学习目标

理解执行策略带来的并行机会、语义限制与异常差异，避免共享状态数据竞争。

## 核心知识点

- **执行策略（execution policy）**：`seq`、`par`、`par_unseq` 和 C++20 的 `unseq` 指示允许的执行方式，而非性能承诺。
- **独立迭代**：并行调用次序通常未指定；元素处理应彼此独立，或通过算法规定的归约来合并结果。
- **向量化**：`unseq`/`par_unseq` 允许同一线程内交错执行，不可在回调中依赖普通互斥锁等阻塞同步。
- **归约（reduction）**：`reduce` 可改变结合次序；运算应满足适当的结合、交换要求，浮点结果可能不同。
- **实现支持**：标准库可以选择串行执行；工具链也可能需要额外后端配置，必须实测。

## 最小示例

```cpp
#include <algorithm>
#include <execution>
#include <vector>
int main() {
    std::vector<int> v(1000);
    std::for_each(std::execution::par, v.begin(), v.end(),
                  [](int& x) { x = 1; });
}
```

## 常见陷阱

- 在回调中无同步地写同一个计数器会造成数据竞争。
- 不要假定并行策略一定更快；小输入的调度成本可能占主导。
- 标准执行策略下用户函数抛出的异常通常导致 `std::terminate`，不能按普通循环理解。
