# 6.4 运算符重载（Operator Overloading）

## 学习目标

为用户自定义类型提供自然且一致的运算符，同时理解成员与非成员重载的选择和语言限制。

## 核心知识点

- **运算符重载（operator overloading）**：为至少含一个类或枚举操作数的既有运算符定义行为，不能创造新符号。
- **成员重载**：左操作数隐含为 `*this`；赋值、下标、调用和成员访问箭头等运算符必须或通常适合作为成员。
- **非成员重载**：对称二元运算常写成非成员，使左右操作数都能参与转换；需要私有访问时可声明 `friend`。
- **复合赋值**：先实现 `+=` 等修改操作，再用它定义 `+`，可减少重复并保持语义一致。
- **比较**：C++20 可默认 `operator==` 或三路比较 `operator<=>`，由成员比较组合出一致关系。
- **转换控制**：单参数构造函数可能参与运算符转换；不希望隐式转换时应标记 `explicit`。

## 最小示例

```cpp
struct Counter {
    int n{};
    Counter& operator+=(Counter r) { n += r.n; return *this; }
    friend Counter operator+(Counter l, Counter r) { return l += r; }
    bool operator==(const Counter&) const = default;
};
int main() { return (Counter{2} + Counter{3}).n == 5 ? 0 : 1; }
```

## 常见陷阱

- 运算符优先级、结合性和操作数个数不能通过重载改变。
- `operator+` 若偷偷修改操作数会违背直觉；修改行为应留给 `+=`。
- 不要为无自然含义的操作强行套用符号，具名函数更清楚。
