# 6.2 复制与移动（Copy and Move）

## 学习目标

区分复制与移动的语义和触发条件，为拥有资源的类型实现安全赋值，并优先复用标准资源类型。

## 核心知识点

- **复制（copy）**：从源对象建立独立的等价值；复制后修改一方通常不应意外影响另一方。
- **移动（move）**：把可转移资源从即将不用的对象交给目标，源对象仍须可析构、可赋值，但值通常未指定。
- **右值引用（rvalue reference）**：形如 `T&&`，让重载可识别临时对象或显式转换后的可移动对象。
- **移动请求**：`std::move` 只做值类别转换，本身不移动数据；实际行为由接收方的移动操作完成。
- **自赋值**：复制和移动赋值都应在对象赋给自身时保持有效，优先借助成员类型的可靠操作实现。
- **异常保证**：先获得新资源再替换旧资源，能避免失败时破坏目标；标准容器也偏好 `noexcept` 移动。

## 最小示例

```cpp
#include <memory>
class Buffer {
    std::unique_ptr<int[]> p_;
    std::size_t n_{};
public:
    explicit Buffer(std::size_t n) : p_{std::make_unique<int[]>(n)}, n_{n} {}
    Buffer(Buffer&&) noexcept = default;
    Buffer& operator=(Buffer&&) noexcept = default;
    Buffer(const Buffer&) = delete;
    Buffer& operator=(const Buffer&) = delete;
};
```

## 常见陷阱

- 移动后不要假定源对象仍保留原值，除非类型契约明确保证。
- 从 `const` 对象通常无法真正移动资源，因为移动构造函数一般需要修改源对象。
- 手写析构函数可能抑制隐式移动操作；检查并显式声明所需语义。
