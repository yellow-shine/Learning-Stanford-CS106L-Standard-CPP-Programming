# 19.5 建议（Advice）

## 学习目标

以现代、可移植且可逐步迁移的方式维护 C++，把兼容约束放在清楚的边界。

## 核心知识点

- 为项目明确最低语言和标准库版本，用持续集成在实际支持的编译器组合上构建。
- 新增代码优先值语义、RAII、标准容器、算法与概念，不为模仿遗留代码继续扩散裸资源所有权。
- 与 C 或旧系统互操作时建立薄边界，立即把错误码、资源句柄和缓冲区转换成现代 C++ 类型。
- 迁移应有测试保护并逐步完成；先消除未定义行为和所有权混乱，再采用改善接口的新特性。

## 最小示例

```cpp
#include <span>
int sum(std::span<const int> xs) {
    int result{};
    for (int x : xs) result += x;
    return result;
}
int main() { int a[]{1,2,3}; return sum(a)==6 ? 0 : 1; }
```

## 常见陷阱

- 不要一次性重写稳定系统只为追新，也不要永久停留在最低共同子集；边界隔离能让内部安全演进。
- 兼容性判断应由目标标准、ABI 文档和持续构建验证，不能只凭单个平台上的一次成功。
