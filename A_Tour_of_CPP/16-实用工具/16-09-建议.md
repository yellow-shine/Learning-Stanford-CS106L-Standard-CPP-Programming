# 16.9 建议（Advice）

## 学习目标

将实用工具用于强化类型、寿命和诊断，而不是用它们隐藏设计问题或绕过语言规则。

## 核心知识点

- **单位入类型**：用 `chrono::duration` 表达时间，避免靠变量名区分秒、毫秒等约定。
- **直接调用优先**：lambda 或普通函数足够时直接使用；仅在确需类型擦除时采用 `std::function`。
- **约束优先**：公开泛型接口使用概念，内部按类型分支再使用 `if constexpr` 和类型特征。
- **位置自动采集**：以 `source_location` 默认参数记录调用点，避免要求调用者手填文件和行号。
- **移动克制**：只在转移所有权或实现转发时使用 `move`/`forward`，移动后立即重置或停止依赖旧值。
- **正常清理**：优先返回或抛出可处理异常，让 RAII 生效；立即终止只用于无法恢复的边界。

## 最小示例

```cpp
#include <chrono>
#include <source_location>
struct Timeout { std::chrono::milliseconds value; };
void report(Timeout, std::source_location = std::source_location::current()) {}
int main() {
    using namespace std::chrono_literals;
    report(Timeout{250ms});
}
```

## 常见陷阱

- 不要用类型擦除掩盖本可静态表达的简单调用关系。
- 不要把源位置字符串当稳定 API 或隐私安全的数据。
- 不要用 `_Exit` 逃避资源所有权设计；它会跳过正常清理。
