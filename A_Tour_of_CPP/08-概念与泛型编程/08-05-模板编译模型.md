# 8.5 模板编译模型（Template Compilation Model）

## 学习目标

理解模板定义为何通常放在头文件中，以及解析、实例化、显式实例化和名称查找对构建的影响。

## 核心知识点

- **两阶段处理**：模板定义先解析非依赖内容，实例化时再检查依赖于模板实参的名称与表达式。
- **定义可见性**：隐式实例化需要看到完整模板定义，因此类模板和函数模板常定义在头文件中。
- **实例化点**：使用具体模板实参的上下文触发实例化，相关类型及操作必须在此满足约束。
- **显式实例化**：可在一个翻译单元生成指定实参版本，并以 `extern template` 抑制其他单元重复实例化。
- **单一定义规则（ODR）**：多个翻译单元中的模板定义必须一致；头文件定义通常依靠内联语义安全合并。
- **实参相关查找（ADL）**：对依赖实参的非限定函数调用会在实例化时搜索关联命名空间，支持可扩展泛型操作。

## 最小示例

```cpp
// 示例为多文件结构，不能作为单一源文件独立编译。
// twice.hpp
#pragma once
template<typename T> T twice(T x) { return x + x; }
// main.cpp
// #include "twice.hpp"
// int main() { return twice(3) == 6 ? 0 : 1; }
```

## 常见陷阱

- 只在 `.cpp` 中定义模板、却在别处隐式实例化，往往得到未定义引用。
- 依赖名称的查找规则复杂；优先使用清楚的限定名和标准定制方式。
- 显式实例化只应在编译时间或代码体积确成问题时引入。
