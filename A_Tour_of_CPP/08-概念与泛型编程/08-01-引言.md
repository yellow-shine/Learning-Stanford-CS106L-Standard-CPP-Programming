# 8.1 引言（Introduction）

## 学习目标

理解泛型编程如何围绕一组语义要求编写算法，并用 C++20 概念把这些要求纳入接口。

## 核心知识点

- **泛型编程（generic programming）**：依据类型共同满足的操作和语义编写算法，而不依赖具体表示。
- **概念（concept）**：命名模板参数约束的编译期谓词，用于声明可接受类型集合。
- **需求（requirement）**：可包括有效表达式、关联类型、返回类型与语义规则；编译器只能检查其中可形式化部分。
- **约束模板**：可用受限模板参数、`requires` 子句或 `requires` 表达式描述接口条件。
- **重载选择**：候选都可用时，更强、更具体的约束可优先，从而直接表达算法分派。
- **静态多态**：满足概念的类型无需共同基类，算法仍能在编译期选择并优化具体操作。

## 最小示例

```cpp
#include <concepts>
template<typename T>
concept Addable = requires(T a, T b) {
    { a + b } -> std::same_as<T>;
};
template<Addable T>
constexpr T twice(T x) { return x + x; }
int main() { static_assert(twice(4) == 8); }
```

## 常见陷阱

- 表达式可编译不等于满足语义，例如一个不满足结合律的 `+` 仍可能通过语法检查。
- 概念应描述调用者关心的能力，而不是罗列某个现有类型的全部成员。
- 约束不能替代运行期数据检查；它只处理编译期类型条件。
