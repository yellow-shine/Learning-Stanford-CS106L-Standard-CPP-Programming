# 8.6 建议（Advice）

## 学习目标

建立现代泛型接口的实践准则：用标准概念表达最小要求，保持算法通用，同时控制复杂度与诊断成本。

## 核心知识点

- **概念命名语义**：名称应表达能力或关系，如 `sortable`，而不是实现细节的偶然集合。
- **最弱充分约束**：只要求算法实际依赖的能力，让更多类型可用，又确保函数体不会出现迟来的错误。
- **标准概念优先**：复用 `<concepts>` 与 `<ranges>` 中的概念，获得一致术语和可靠的约束包含关系。
- **约束靠近接口**：把要求写在声明处，使调用失败时诊断指向接口，而非深层实现。
- **算法与策略分离**：把比较器、投影等作为参数，避免按每种业务规则复制算法。
- **控制实例化**：公共模板保持短小；稳定且与类型无关的工作放入普通函数，降低构建与代码体积成本。

## 最小示例

```cpp
#include <concepts>
#include <ranges>
template<std::ranges::input_range R>
requires std::equality_comparable<std::ranges::range_value_t<R>>
bool all_equal(const R& r) {
    auto it = std::ranges::begin(r), last = std::ranges::end(r);
    if (it == last) return true;
    const auto& first = *it++;
    for (; it != last; ++it) if (!(*it == first)) return false;
    return true;
}
```

## 常见陷阱

- 不要把实现中的每个表达式机械拼成概念；接口应描述有意义且可复用的契约。
- 不要为了展示模板技巧替代简单重载或标准算法。
- 编译期通过仍不保证语义正确，应以代表性类型验证行为和复杂度。
