# 3.2 分离编译（Separate Compilation）

## 学习目标

掌握声明放入接口、定义放入实现的传统组织方式，并理解编译器与链接器各自负责的问题。

## 核心知识点

- **分离编译（separate compilation）**：各翻译单元独立编译为目标文件，最后由链接器组合成程序。
- **头文件声明（header declaration）**：多个源文件共享的函数、类型和常量接口通常置于头文件。
- **定义（definition）**：非内联函数一般在一个 `.cpp` 中定义，避免违反单一定义规则。
- **包含保护（include guard）**：宏保护或 `#pragma once` 防止同一翻译单元重复包含头文件内容。
- **单一定义规则（One Definition Rule, ODR）**：程序中的实体必须满足规定的定义数量与一致性要求。
- **链接（linking）**：解析跨翻译单元符号；未定义引用和重复定义通常在此阶段报告。

## 最小示例

```cpp
// math.hpp
#pragma once
int square(int);

// math.cpp
// #include "math.hpp"
int square(int x) { return x * x; }

// main.cpp
// #include "math.hpp"
// int main() { return square(3) == 9 ? 0 : 1; }
```

以上需拆成三个文件并由构建系统共同编译，代码块仅展示结构。

## 常见陷阱

- 在头文件中定义普通非 `inline` 函数，包含于多个翻译单元后重复定义。
- 头文件依赖包含顺序，自己单独包含时不能编译。
- 修改实现细节却把它放在公共头文件中，造成不必要的级联重编译。
