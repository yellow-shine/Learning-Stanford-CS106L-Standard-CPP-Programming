# 3.5 建议（Advice）

## 学习目标

以最少耦合组织程序边界，让接口易懂、实现可替换、构建错误容易定位。

## 核心知识点

- **接口最小化（minimize interfaces）**：只导出调用者确实需要的声明，辅助函数留在实现文件或内部命名空间。
- **依赖显式化（explicit dependencies）**：每个头文件直接包含自身声明所需内容，不依赖包含者碰巧先包含其他文件。
- **定义单一来源（single source of definition）**：普通函数和变量保持一个定义；适用时才用 `inline` 或内联变量。
- **名称限定（name qualification）**：跨命名空间使用限定名，局部范围才谨慎使用 `using` 声明。
- **值返回优先（prefer value return）**：让函数通过返回值交付结果，多个相关结果可组成结构体。
- **边界稳定（stable boundary）**：将频繁变化的实现细节藏在 `.cpp`，减少调用者重编译和连锁修改。

## 最小示例

```cpp
#include <string>

namespace app {
struct Parsed { std::string name; int count; };
Parsed default_config() { return {"worker", 4}; }
}
int main() {
    const auto cfg = app::default_config();
    return cfg.count > 0 ? 0 : 1;
}
```

## 常见陷阱

- 创建“万能公共头文件”，使所有翻译单元依赖整个项目。
- 在头文件暴露内部宏、未命名空间辅助名称或可变全局变量。
- 为微小接口提前设计复杂插件层；先保持清晰边界即可。
