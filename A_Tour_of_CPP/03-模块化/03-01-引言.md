# 3.1 引言（Introduction）

## 学习目标

理解模块化如何通过接口边界控制依赖，并区分源代码组织、名称组织与二进制构建。

## 核心知识点

- **模块化（modularity）**：将程序拆成职责明确、依赖有限的组成部分，使修改影响保持局部。
- **接口（interface）**：向使用者公开名称、类型和契约；稳定接口不应泄漏不必要的实现细节。
- **实现（implementation）**：完成接口承诺，可独立修改和编译，只要外部可观察行为保持一致。
- **翻译单元（translation unit）**：一个源文件经预处理后的编译输入，是传统分离编译的基本单位。
- **头文件机制（header mechanism）**：声明通过 `#include` 共享，本质是文本替换，需要包含保护与定义规则配合。
- **C++20 模块（C++20 modules）**：用 `export` 和 `import` 显式传递接口，减少文本包含问题；工具链支持和构建方式依实现而异。

## 最小示例

```cpp
// 单文件示例：以命名空间展示接口边界；真正分离见后续小节。
#include <iostream>
namespace stats { double mean(double a, double b) { return (a + b) / 2; } }
int main() { std::cout << stats::mean(2, 4) << '\n'; }
```

## 常见陷阱

- 把“文件多”误认为模块化好；关键在依赖方向与接口质量。
- 在公共接口中暴露仅供实现使用的类型、宏或可变全局状态。
- 假设所有 C++20 编译器和构建系统对模块已有一致工作流。
